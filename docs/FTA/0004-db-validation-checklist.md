# FTA 0004: DB検証チェックリスト

対象: [`db/prompts.json`](../../db/prompts.json)

## 目的

DBを再編したあとに、壊れやすい箇所を機械的に確認するためのチェックリスト。

このリポジトリでは、バリデーションはビルド時に効くのが望ましい。  
手作業レビューだけに頼ると、系列の統合やID変更で参照切れが残りやすい。

## 必須チェック

### 1. IDの一意性

- `blocks.id` が重複していないこと
- `templates.id` が重複していないこと
- 旧IDと新IDが同名で共存していないこと

### 2. 参照整合性

- `template.blocks` の参照先がすべて存在すること
- `template.uses` を残すなら、その参照先がすべて存在すること
- `block.related` の参照先がすべて存在すること
- `block.variant_of` の参照先が存在すること

### 3. 系列の親子関係

- `variant_of` は親子関係だけに使われていること
- `related` は「近い参照」に限られていること
- `aliases` は検索語の補助に限定されていること

### 4. 役割の衝突

- `blocks` と `uses` が同じ意味を二重表現していないこと
- `layout` / `scene` / `pose` / `outfit` の役割が混ざっていないこと
- `pack` の意味が「文言」「ルール」「補助情報」のどれかに寄りすぎていないこと

### 5. 画像参照

- `artifacts.path` が実在すること
- `artifacts.path` がプロジェクトルート基準の相対パスであること
- 同じ画像が別名で重複登録されていないこと

## 推奨チェック

### 6. 系列の重複判定

以下のようなテンプレートは、重複候補として警告を出す。

- 差分が季節だけ
- 差分が背景だけ
- 差分がポーズだけ
- 差分が文言だけ

### 7. ファミリー単位の可視化

- `morning_*`
- `travel_*`
- `reading_*`
- `cosplay_*`
- `poker_*`
- `cardgame_*`
- `joinwars_*`
- `logo_*`
- `reply_*`
- `archive_*`
- `memory_*`

上の系列ごとに、一覧で束ねて見えること。

### 8. UI上の読みやすさ

- 似たテンプレートが散らばっていないこと
- 検索結果で親系列が先に見えること
- `artifacts` があるテンプレートは、画像ありで識別しやすいこと

## 実装候補

このチェックは、次の順で実装すると壊れにくい。

1. JSONロード時の重複ID検査
2. 参照整合性検査
3. 画像ファイル存在検査
4. 系列重複の警告
5. UI表示用の系列グルーピング

### 実行コマンド

- `python3 scripts/validate_db.py`
- `python3 build.py`

## 運用ルール

- 追加したテンプレートは、必ず親系列を確認してから入れる
- 新しい派生を増やすときは、まず既存の `variant_of` を探す
- 画像を増やしたら、`artifacts.path` と実ファイル名を必ず突き合わせる

## 結論

DBのスケール問題は、件数が増えたあとに起きるのではなく、  
**似た構造を無秩序に増やした時点で始まる**。

したがって、再編と同時に検証を固めるのが最優先である。
