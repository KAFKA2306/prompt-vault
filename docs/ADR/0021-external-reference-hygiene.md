# ADR 0021: 外部参照の衛生基準を「借りる / 変える / 一目で修正」に分ける

## ステータス

承認済み

## コンテキスト

外部のゲーム、作品、ブランド、UI、カード枠、配色、固有名詞には、混同や既視感が起きやすい。

このリポジトリでは、抽象化して使ってよい要素と、必ず変える要素と、見た瞬間に修正する要素を分けて運用する。

## 決定事項

### 1. 借りてよいもの

- 仕組み
- 流れ
- 抽象化した遊び方
- ルールの構造
- 一般的な進行の型

### 2. 必ず変えるもの

- 世界観
- 設定
- 固有名詞
- タイトル
- キャラ名
- ロゴ
- UI
- カード枠
- 配色
- 公式っぽい文言

### 3. 一目で修正対象のもの

- 元ネタが判別できる名前
- 元ネタが判別できる見た目
- 元ネタが判別できる UI
- 元ネタが判別できる配色
- 元ネタが判別できるカード枠
- `〇〇風`
- `inspired by`

### 4. キャラクターは別人レベルで再設計する

- 顔つき
- 髪型
- 髪色
- 服装
- シルエット
- 小物
- 表情の癖

### 5. 公式っぽさを避ける

- 公式ロゴの連想を残さない
- 公式 UI の連想を残さない
- 公式カードデザインの連想を残さない
- 商業印象をそのまま残さない

## 運用ルール

- メカニクスだけを抽象化して使う。
- 名前は必ず変更する。
- 見た目は必ず再設計する。
- 一目で元ネタが分かるなら、その要素は修正する。
- `〇〇風` と `inspired by` は書かない。

## 理由

- 著作権はアイデアや仕組みではなく、表現を保護する。
- 商標は、名前や見た目の混同を問題にする。
- trade dress は、全体の見た目や商業上の印象を問題にする。

## 結論

借りる中心は仕組みと流れ。

変える中心は名前と見た目。

見た瞬間に元ネタが分かるものは修正対象。
