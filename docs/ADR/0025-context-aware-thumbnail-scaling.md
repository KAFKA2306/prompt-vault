# ADR 0025: コンテキストに応じたサムネイル表示の最適化

## ステータス

承認済み

## コンテキスト

Prompt Vault のフロントエンド（`app.js`）では、メインギャラリーと詳細画面の「似た構成のプロンプト（関連リスト）」で同じサムネイル描画関数（`renderArtifactThumb`）を使用している。

しかし、表示場所によって求められるデザイン要件が異なっていた：

- **メインギャラリー**: `minmax(280px, 1fr)` のグリッド、アスペクト比 16:10。
- **関連リスト**: 固定幅 140px、アスペクト比 4:3。

これに対し、描画関数が生成する HTML が共通だったため、以下の問題が発生していた：

- 画像アセットが `object-fit: cover` により、意図しない倍率で切り取られて表示される。
- 音声（AUDIO）や画像なし（No Image）のプレースホルダーが、小型のリスト内でもメインギャラリー用の大きなスケールで描画され、視覚的に「異常に大きく」見える。

## 決定

1. **描画関数のコンテキスト対応**:
   `renderArtifactThumb(artifact, className)` のように、呼び出し側から CSS クラスを注入できるように拡張する。
2. **関連リスト専用スタイルの適用**:
   詳細画面の関連リスト表示時には `modal-related-thumb` クラスを付与する。
3. **プレースホルダーのスケーリング調整**:
   `style.css` において、`modal-related-thumb` クラスが付与された場合の `audio` 波形（Waveform）やラベルのサイズを、小型枠に合わせて個別に定義する。
4. **トリミング制御の明確化**:
   画像アセットに対して `object-fit` を場所ごとに最適化できるよう、共通の `img` セレクタではなくクラスベースの制御に寄せる。

## 理由

- 1 つの描画ロジックで複数の表示箇所を賄うことで保守性を維持しつつ、CSS クラスによって各コンテキストに最適な「倍率（スケーリング）」を実現できる。
- 関連リストのような狭い領域でプレースホルダーが巨大に見える問題を解消し、UI 全体のプレミアムな質感（Quiet UI 2026）を維持するため。

## 影響

- 「似た構成のプロンプト」セクションのサムネイルが 140px / 4:3 で正しく表示される。
- 音声アセットの波形グラフィックが、小型サムネイル内でも適切な密度で表示される。
- メインギャラリー側の表示には影響を与えず、既存の 16:10 レイアウトを維持できる。

## 運用

1. 新しい表示箇所（サイドバーや検索結果など）でサムネイルを使う場合は、`renderArtifactThumb` にその場所専用のクラスを渡す。
2. そのクラスに対するアスペクト比やプレースホルダーのスケールを `style.css` に定義する。
3. `object-fit: cover` による拡大感が強すぎる場合は、`contain` への切り替えを検討する。
