# ADR 0022: docs と skills は推論を書かず、確認できる事実だけを書く

## ステータス

承認済み

## 決定

`docs/*` と `.agents/skills/*` には、次の3種類だけを書く。

- ファイルから直接確認できる事実
- 明示された決定事項
- 実行手順

次の内容は書かない。

- 推論
- 未確認の仕様
- 未実装の機能
- 曖昧な一般論

## 運用

- 仕様を書くときは、根拠になるファイル名を明示する。
- 根拠がない文は削る。
- 確認できない点は `未確認` と書く。
- `できる` と断言するのは、実際の実装か手順が確認できる場合だけにする。

## 影響

- docs と skills の内容が、確認可能な情報に寄る。
- 未実装の期待を文書に混ぜにくくなる。
- 読者がファイルを見れば、どこまで確定しているかを判断しやすくなる。
