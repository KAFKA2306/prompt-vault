# ADR 0026: 人格発展記録（PERSONA_DEVELOPMENT.md）の更新プロセス

## ステータス

承認済み

## コンテキスト

`db/prompts.json` には日々の生成ログや活動が記録されるが、これらは断片的であり、Kafka の人格としての整合性や長期的な変遷を把握するには不十分である。AIエージェントが Kafka として一貫したトーンで振る舞うためには、事実に基づいた要約的なリファレンスが必要である。

## 決定

1. **定期的な知識統合**: `db/prompts.json` の `generated` 成果物、`voice_script`、および外部ログ（`tweetsdb.json` 等）を定期的に監査し、重要な出来事や属性の獲得を `docs/PERSONA_DEVELOPMENT.md` に追記する。
2. **正本としての利用**: `PERSONA_DEVELOPMENT.md` を人格の「正本（Source of Truth）」と定義する。新規プロンプト、`purpose`、`voice_script` の生成時には、必ず本ドキュメントを参照して整合性を担保する。
3. **厳密な記述ルール**:
    - 事実（実際に生成・採用されたログ）に基づき、推論や虚飾を排除する。
    - Kafka の発話トーンを尊重した、厳密で透明感のある日本語で記述する。
    - 2026年基準の「Quiet UI」や「Zero-Fat」の思想に合わせ、冗長な記述を避け、箇条書きや表形式を活用する。

## 影響

- エージェントが Kafka として振る舞う際の「人格のブレ（Persona Drift）」を最小化できる。
- 過去の活動ログが構造化され、新しいワールドやコンテンツへの適応が容易になる。
- `db/prompts.json` の肥大化に伴う文脈喪失を防ぎ、長期的な人格の発展を追跡可能にする。
