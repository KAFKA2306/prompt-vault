# ADR 0028: 破壊的コマンド実行前プレフライト安全ハーネスの導入

## 1. 背景 (Context)
自律エージェントの運用において、ワーキングツリーの整理やクリーンアップの目的で `git clean -fd` や `git restore` などの破壊的コマンドが実行されるケースがある。しかし、エージェントの誤判断や不手際により、ユーザーが進行中であった未追跡（Untracked）な生成画像アセットや、データベース（`db/prompts.json`）の未コミットの変更が完全に消失し、作業が巻き戻るという重大なインシデントが発生した。

人間の注意力やLLMの自己申告に依存する再発防止策は、確実性に欠け機能しない。破壊的操作から未コミット・未追跡アセットを保護するためには、「システム的・物理的なコマンド導線のハーネス化（遮断器）」による恒久解決が必要である。

## 2. 意思決定 (Decision)
リポジトリの破壊的変更を伴う操作に対して、以下の「プレフライト破壊的コマンド制限ハーネス」を導入する。

### 基本ルール
1. **直接実行の禁止**: `git clean -fd` などの破壊的コマンドは、エージェントから直接実行することを永久に禁止する。
2. **ハーネス経由の義務化**: すべてのクリーンアップ操作は `scripts/safe_git_clean.sh` を介して行わなければならない。
3. **機械的 PASS/FAIL 判定**: 実行可否の判断は機械的スクリプトの Exit Code のみに依拠する。LLMによる「安全である」という推論や自己申告は一切受け入れない。
4. **証拠保存**: 判定および操作ログは必ず `runs/destructive_guard/YYYYMMDD-HHMMSS/` 内に永続化される。

### 安全制限の判定基準
- `db/prompts.json` に未コミットの変更が存在する場合は **FAIL (実行不可)**。
- `artifacts/`, `dist/artifacts/`, `generated/`, `tmp/` などに未追跡（Untracked）な画像ファイル（`.png`, `.webp`, `.jpg`, `.jpeg`）が存在する場合は **FAIL (実行不可)**。
- 破壊的操作によって1ファイルでも画像が削除される恐れがある場合は **FAIL (実行不可)**。

---

## 3. 実装仕様 (Implementation Specifications)

### 3.1 プレフライト検査スクリプト (`scripts/guard_destructive.sh`)
Gitのステータスおよび対象ディレクトリの画像ファイルをスキャンし、未追跡の画像または変更された DB ファイルが検出された場合に Exit Code 1 で処理を拒絶する。

### 3.2 安全クリーンラッパー (`scripts/safe_git_clean.sh`)
上記プレフライト検査を実行し、完全に安全（PASS）と判定された場合のみ `git clean -fdn` (dry-run) を実行して安全性を検証する。dry-run 段階で削除対象がある場合は実行をブロックする。

---

## 4. エージェントの行動誓約 (Agent Contract)
- エージェントは、破壊的コマンド（`git clean`, `git restore`, `git reset`, `rm`, `mv`）を実行する前に、必ず `scripts/guard_destructive.sh` を実行して安全性を保証しなければならない。
- 安全判定が **FAIL** の場合、エージェントは直ちに処理を停止し、証拠ディレクトリのパス（Evidence Path）と検出された未追跡ファイルの一覧のみをユーザーに報告しなければならない。
- システムの残存データを物理的な根拠なく「復旧可能である」と虚偽の要約・申告を行ってはならない。

## 5. 影響 (Consequences)
- **メリット**: 人為的ミスによる未コミット・未追跡アセットの永久喪失を100%防止できる。
- **デメリット**: 未コミットの変更がある状態でのクリーンアップ手順が厳格化されるが、安全性の対価として許容される。
