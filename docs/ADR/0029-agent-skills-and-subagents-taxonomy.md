# ADR 0029: エージェント開発における Skills と Subagents のタクソノミー（分類法）定義

## ステータス

提案 (Proposed)

## コンテキスト

Prompt Vault および関連するリポジトリ（VRChat ツール、音声パイプライン、NAV システム等）の開発・監査において、AI エージェントが実行するタスクにはいくつかの強力な反復パターン（zero-trust loops, 整合性監査, ADR生成, CI トリアージ等）が存在します。
これらのタスクを「再利用可能なワークフロー（Skills）」と「限定された調査的役割（Subagents）」に明確に分類し、エージェントが直面する問題に対して適切なアプローチを選択できるようにします。

## 決定事項

エージェントの処理モデルを以下の 2 つの抽象レイヤーに分割します。

### 1. Skills (再利用可能な定型ワークフロー)

あらかじめ定義された、決定論的かつ予測可能なステップからなる再利用可能な手順。

#### ① `zero-trust-delivery-audit`

- **ユースケース**: 生成された出力の検証、不完全/モック化された実装の検出、リリース承認、CIアセット検証

- **ワークフロー**:
  1. 生成された出力の収集
  2. ファイルシステム上の実在性検証
  3. 実行環境/ランタイムにおける現実性（モックでなく実動するか）の検証
  4. 宣言されたアセットと実際のアセットの比較
  5. `PASS` / `FAIL` / `UNVERIFIED` の判定出力
  6. 根拠（エビデンス）となるパスの添付

#### ② `repo-structure-governance`

- **ユースケース**: DESIGN.md の作成、ADRエコシステムの整備、リポジトリ構成の標準化、ディレクトリ命名規則の検証、アーキテクチャの乖離（ドリフト）検出

- **ワークフロー**:
  1. リポジトリのレイアウトおよび構成の検査
  2. 責任範囲が混在している箇所の特定
  3. ライフサイクルの汚染（開発用/本番用などの混在）の検出
  4. カノニカル（標準的）なリポジトリ構造の提案
  5. 移行推奨案の出力

#### ③ `prompt-db-integrity-audit`

- **ユースケース**: `prompts.json` の監査、ブロック境界の検証、アイデンティティリーク（Character Identity Leak）の検出、テンプレート汚染の検出

- **ワークフロー**:
  1. プロンプトデータベース（JSON）の読み込み
  2. スキーマおよびメタルールの検証
  3. 混在した懸念事項の検出
  4. 重複または類似するセマンティックブロックの特定
  5. クリーンアップ/整理候補の提示

#### ④ `research-to-implementation-gap-check`

- **ユースケース**: 論文や仕様ドキュメントと実際の実装との比較、アーキテクチャの整合性検証、ベンチマーク/再現精度のチェック

- **ワークフロー**:
  1. ドキュメントやソースからの主張（Claims）の収集
  2. 実際の実装コードの検査
  3. 欠損しているコンポーネントのマッピング
  4. 進捗の分類 (`implemented` / `partial` / `conceptual only` / `mocked`)
  5. リスクおよびギャップ情報の出力

---

### 2. Subagents (限定された調査的ペルソナ/役割)

分岐する推論や調査主体のデバッグを実行する、自律的なエージェントロール。

#### ① `ci-triage-investigator`

- **役割と振る舞い**:
  - CI の失敗、ビルドエラー、依存関係の競合、Windows ツールチェインエラー等のトリアージ
  - エラーの再現、問題箇所の分離、根本原因の分類、最初にエラーを引き起こした依存/ファイルの特定、最小限の修正案の提示

#### ② `release-readiness-reviewer`

- **役割と振る舞い**:
  - リリースの準備、公開可能性の検証、ドキュメント/変更ログ/バージョン整合性の検証
  - 変更ログの網羅性チェック、バージョン不一致の検出、ドキュメントの欠落検知、アセットの存在確認、リンク切れのチェック、リリース受け入れチェックリストの生成

#### ③ `spec-to-reality-auditor`

- **役割と振る舞い**:
  - 仕様（Spec）、ADR、README、実際の実装、実行時動作の乖離（Drift）を比較し特定する
  - 判定結果の出力 (`aligned` / `drifted` / `unverifiable` / `contradicted`)

#### ④ `evidence-collector`

- **役割と振る舞い**:
  - 報告書作成、ログの収集、監査ログの構築、再現エビデンスの収集
  - 必要パスの収集、ログのダンプ、出力結果の要約、エビデンス構造の正規化

---

## 影響とメリット

1. **一貫性の向上**: 新しい自動検証スクリプトやCI設定を構築する際、上記で定義された Skills / Subagents のステップをベースとすることで、実装のブレを防ぎます。
2. **監査モデルの明確化**: リポジトリの監査プロセスにおいて、何が Skills（手順通りに実行可能なテスト等）で、何が Subagents（AI による自律調査が必要な問題）なのかを明確に識別できます。
